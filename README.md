# CtrlFit - Fitting controller-observer pairs

`ctrlfit` is a `jax-sysid`-based library for training recurrent output-feedback surrogate controllers from trajectories generated by an expert controller-observer pair, such as an NMPC controller coupled with an EKF.

The package provides:

- generic JAX-vectorized expert-data collection;
- output-feedback dataset formatting;
- optional data scaling;
- single-fit and parallel-fit training;
- optional two-step Lyapunov regularization;
- save/load, surrogate simulation, and plotting helpers.

The surrogate architecture, plant model, and expert controller-observer remain user-defined. For more detail, see the [paper](https://doi.org/10.48550/arXiv.2606.16930) and the [user guide](doc/ctrlfit_user_guide.pdf).

## Installation

From the package directory:

```bash
pip install .
```

This also installs the dependencies used by the CSTR example. Alternatively, install the same dependencies from `requirements.txt`:

```bash
pip install -r requirements.txt
```

## Overview

`ctrlfit` trains a recurrent surrogate controller for an expert controller-observer pair. The plant is

$$
\begin{equation}
    \mathcal{P}:\, \begin{cases}
        \begin{aligned}
            x_{k+1} &= f_\mathcal{P}(x_k, u_k), \\
            y_k     &= g_\mathcal{P}(x_k) + \eta_k,
        \end{aligned}
    \end{cases}
\end{equation}
$$

the expert controller-observer pair is

$$
\begin{equation}
\mathcal C:\quad
\begin{cases}
    \begin{aligned}
        \chi_k &= \mathcal O(\chi_{k-1},y_k,u_{k-1}),\\
        \hat{x}_k &= h(\chi_k),\\
        u_k &= \kappa(\hat{x}_k,\bar y),
    \end{aligned}
\end{cases}
\end{equation}
$$

and the recurrent surrogate is

$$
\begin{equation}
\mathcal S:\quad
\begin{cases}
    \begin{aligned}
        z_{k+1} &= f_z(z_k,y_k,\bar y;\theta),\\
        \hat{u}_k &= f_u(z_k,y_k,\bar y;\theta).
    \end{aligned}
\end{cases}
\end{equation}
$$

The user-defined `jax-sysid` recurrent `Model` receives an output-feedback signal such as

$$
w_k=[y_k,\bar y]
$$

and predicts the expert control input.

## Controller Learning

```python
from ctrlfit import ctrlfit

model, training_info = ctrlfit(
    model=model,
    U=U_data,
    Y=Y_data,
    Y_ref=Y_ref_data,
    init_params_fcn=init_fcn,
)
```

`U`, `Y`, and `Y_ref` are required. Each may describe one trajectory or a list of trajectories. `Y_ref` may also be a scalar or vector constant, which is expanded internally before `ctrlfit` forms `[Y, Y_ref]`.

The plant-side `state_fcn(x, u)` and `output_fcn(x)` are optional for plain supervised fitting. Provide them when using the built-in Lyapunov regularizer, physical closed-loop validation, or plant rollouts.

`init_params_fcn(seed)` is recommended for reproducibility and required for parallel fitting. For a single fit, an already initialized `model.params` is also accepted.

Useful fitting options include:

- `X_hat`: observer/state-estimate trajectories. Required when `use_lyap_reg=True`.
- `U_val`, `Y_val`, `Y_ref_val`, `X_hat_val`: optional validation data. Suggested when `use_parallel_fit=True`.
- `use_parallel_fit`, `num_parallel_fit`: train and select among multiple initializations.
- `closed_loop_validation=True`: explicitly select parallel candidates by physical plant rollouts. This requires validation data, plant functions, and `X_hat_val`; otherwise `ctrlfit` warns and uses supervised validation.
- `use_scaling=True`: scale surrogate inputs and targets at the package boundary. Pass `y_mean=None`, `y_gain=None`, `u_mean=None`, and `u_gain=None` to estimate scaling statistics from training data.
- `use_lyap_reg=True`: append the Lyapunov parameter tail and train with the built-in trajectory-based regularizer unless `custom_reg_fcn` is supplied.
- `auto_save_training_info=True`: save the returned training metadata to `ctrlfit_training_info.pkl` after fitting.

The built-in regularizer currently implements only the two-step non-monotonic condition (`m=2`). If another `num_lyap_steps` value is requested, `ctrlfit` warns and uses `2`.

The return value is `(model, training_info)`. `training_info` contains the fitted model, resolved options, timing, scaling metadata, optional Lyapunov metadata, and parallel-fit selection information needed to inspect, save, and reuse the surrogate.

## Collect Expert Data

The package exports a generic fast collector:

```python
from ctrlfit import collect_post_initialization_training_data_fast

dataset = collect_post_initialization_training_data_fast(
    state_fcn,
    output_fcn,
    mpc_fcn,
    ekf_meas_fcn,
    ekf_time_fcn,
    x_ref=x_ref,
    u_ref=u_ref,
    sim_steps=num_sim_steps,
    x0=x0,
    x0_hat=x0_hat,
    P0=P0,
)
```

The callback protocols are:

```python
x_next = state_fcn(x, u)
y = output_fcn(x)
u, mpc_state_next = mpc_fcn(x_hat_corr, x_ref, u_ref, mpc_state)
x_hat_corr, P_corr = ekf_meas_fcn(x_hat_pred, P_pred, y_meas)
x_hat_next, P_next = ekf_time_fcn(x_hat_corr, P_corr, u)
```

The collector uses `jax.lax.scan`, `jax.vmap`, and `jax.jit`. All callbacks and carried states must therefore be JAX-compatible fixed-shape values.

Two starting routes are supported:

- Direct rollout: provide `x0` and `x0_hat`; `P0` defaults to `eye(nx)`.
- Post-initialization: provide `x_minus_M`, `x0_ref`, `u0_ref`, and a positive `init_steps`. The warm-up phase produces `x0`, `x0_hat`, and `P0` before the training window. If `x_hat_minus_M` is omitted, provide `x_s`.

Optional bounds reject invalid trajectories after simulation. By default, the collector also applies a terminal tracking check whose tolerance scales with the reference output and the available measurement-noise standard deviation. Pass `trajectory_filter=None` to disable that check, or pass a callable to replace it with a domain-specific rule. Set `target_num_trajs` to require a specific number of accepted trajectories.

The returned dictionary includes the accepted training signals (`U`, `Y`, `X_hat`, `X_true`, `P`, and terminal values), optional initialization histories, initial training-window values, and collection metadata.

## Save, Load, and Run the Surrogate

Use `training_info` to save, load, and run the fitted surrogate:

```python
from ctrlfit import (
    load_training_info,
    save_training_info,
    simulate_surrogate_closed_loop,
)

save_training_info(training_info, "results/ctrlfit_model.pkl")
model, training_info = load_training_info(
    "results/ctrlfit_model.pkl",
    model=recreated_model,
)

rollout = simulate_surrogate_closed_loop(
    model,
    state_fcn,
    output_fcn,
    reference_trajectory,
    x0_true=x0,
    use_scaling=training_info["scaling_info"]["use_scaling"],
    y_mean=training_info["yyref_mean"][:ny],
    y_gain=training_info["yyref_gain"][:ny],
    u_mean=training_info["u_mean"],
    u_gain=training_info["u_gain"],
)
```

Recreate the recurrent architecture before loading because model definitions belong to user code.

## CSTR Examples

Run the complete NMPC-EKF data-generation, training, and comparison workflow:

```bash
python examples/example_cstr.py
```

To reuse an existing `examples/results/cstr_dataset.pkl` dataset:

```bash
python examples/example_cstr_dataset.py
```

Both workflows write generated artifacts under `examples/results/`; see the [user guide](doc/ctrlfit_user_guide.pdf) for a description of the generated `.pkl` and `.png` files. The complete workflow uses a 30-step post-initialization window, a preset CSTR initialization region, and separate training, validation, and held-out test splits.
